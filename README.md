# WooCommerce plugin for Payme

## Установка

#### Требования

- PHP >= 7.4
- [WordPress 5.x](https://wordpress.org/) или новее
- [WooCommerce 4.x](https://woocommerce.com/) или новее (совместим с HPOS / Custom Order Tables)
- Регистрация в кабинете поставщика [Paycom](http://paycom.uz/)

#### GitHub

Скачайте плагин как ZIP архив.

Загрузите плагин в WordPress

![Upload plugin](images/upload-plugin.png)

...и установите его

![Install plugin from ZIP](images/install-from-zip.png)

Активируйте плагин после установки

![Activate plugin](images/activate-plugin.png)

Откройте страницу настроек WooCommerce

![WooCommerce Settings page](images/woocommerce-settings.png)

Откройте вкладку `Checkout`

![Checkout Tab](images/checkout-tab.png)

Откройте вкладку `Payme` и внесите необходимые данные.

![Payme Settings](images/payme-settings.png)

Скопируйте ваш `Endpoint URL` и внесите его в кабинете поставщика Paycom.

![Set Endpoint URL](images/endpoint-url.png)

> **Nginx + PHP-FPM:** убедитесь, что заголовок `Authorization` доходит до PHP.
> Если callback-запросы Payme получают ошибку авторизации, добавьте в конфиг:
> `fastcgi_param HTTP_AUTHORIZATION $http_authorization;`

## Changelog

### 1.6.0

- **Убрана промежуточная страница при переходе на оплату.** Описание платежа
  можно передать только POST-методом, а POST требует формы в браузере
  покупателя — поэтому полностью отказаться от HTML-страницы нельзя. Но
  раньше эта форма отдавалась на полноценной странице WooCommerce «Оплатить
  заказ», со всей темой, шапкой, меню и стилями — её покупатель и видел как
  лишний шаг. Теперь после «Оформить заказ» браузер попадает на служебный
  endpoint `?wc-api=wc_payme_redirect`, который отдаёт голый HTML-документ
  в несколько сотен байт: только форма и одна строка автоотправки, без темы
  и лишних запросов. Визуально это неотличимо от прямого редиректа.
- Кнопка «Продолжить» и ссылка «Отмена» перенесены внутрь `<noscript>` —
  при включённом JS покупатель не видит ни кнопки, ни мелькающей надписи,
  а при отключённом получает рабочую кнопку вместо тупика.
- Формат URL возврата (без `&`) и отсутствие `callback_timeout` сохранены
  без изменений — счётчик автовозврата на стороне Payme продолжает работать.
- Повторная оплата через «Мой аккаунт → Заказы → Оплатить» по-прежнему идёт
  через штатную страницу WooCommerce: этот путь редкий, и обойти её там
  нельзя без вмешательства в маршрутизацию WooCommerce.

### 1.5.9

- **Починен счётчик автовозврата на странице Payme** («{{ timeout }}» вместо
  числа, страница выглядела зависшей до ручного обновления). Причина
  оказалась не в значении `callback_timeout`, а в **формате URL возврата**.
  В 1.5.2 он был переписан на `add_query_arg()` — формально более
  правильный способ, но он добавляет в URL символы `&`, а фронтенд Payme,
  судя по всему, некорректно разбирает собственный URL, когда внутри
  параметра `back` есть закодированные амперсанды (`%26`), и «теряет»
  параметр `timeout`. Проверено со значениями `callback_timeout` 15, 1000,
  15000 и вовсе без него — решающим фактором является именно `&`.
  Формат URL возврата возвращён к варианту из 1.5.1, где амперсандов нет.
- Заодно устранена причина, ради которой формат вообще менялся в 1.5.2:
  в 1.5.1 значения `order_id` и `key` из такого URL фактически не
  извлекались. Добавлена функция `payme_parse_return_params()`, которая
  корректно разбирает этот формат, а также понимает URL, сформированные
  версиями 1.5.2–1.5.8 — возвраты по заказам, созданным на тех версиях,
  продолжат работать.
- Поле `callback_timeout` больше не передаётся (в рабочей 1.5.1 его тоже не
  было); Payme применяет свой дефолт.

### 1.5.8

- `callback_timeout` возвращён в форму со значением **1000**. Выяснилось, что
  `15000` — это собственный дефолт Payme: он подставляется в URL даже когда
  поле не передаётся вовсе (проверено в 1.5.7). То есть все предыдущие
  попытки «починить» таймер значением 15000 просто дублировали их дефолт.
  Явное значение, отличное от дефолта, — единственный рычаг с нашей стороны.

### 1.5.7

- Поле `callback_timeout` больше не передаётся — Payme применяет свой
  собственный дефолт. Ни одно из значений не работало корректно при тестах
  на живой кассе: `15000` (буквальное прочтение документации, «в
  миллисекундах») оставляло счётчик фактически незавершаемым — страница
  выглядела зависшей до ручного обновления; `15` приводило к отсчёту в
  отрицательные значения. Поскольку собственный дефолт Payme по определению
  согласован с их же логикой отрисовки счётчика, самое надёжное — не
  передавать это поле вообще. Не возвращайте его без проверки на реальной
  кассе.
- Убран задвоившийся блок комментария, оставшийся от правки 1.5.6.

### 1.5.6

- Похоже, найдена настоящая причина «зависания» страницы Payme на каждой
  оплате (не обновлялся счётчик автовозврата, требовалось вручную обновить
  страницу). Плагин передавал `callback_timeout=15000`, ориентируясь на
  формулировку документации «в миллисекундах» (15 секунд). Но в реально
  работающих примерах интеграции у этого поля значение — просто **`15`**,
  без домножения на 1000. Судя по всему, фактическое поведение Payme не
  соответствует буквальному смыслу «миллисекунды» из документации, и
  значение 15000 воспринималось как таймер примерно на 4 часа — отсюда
  ощущение «зависшей» страницы. Значение изменено на `15`.

### 1.5.5

- Возвращено поле «Описание» платежа в кабинете Payme. Метод GET (быстрая
  ссылка, введён в 1.5.2 ради отказа от промежуточной страницы) не
  поддерживает передачу описания платежа — это ограничение самого метода,
  задокументированное у Payme (набор параметров GET: `m`, `ac`, `a`, `l`,
  `c`, `ct`, `cr` — поля для описания там нет). Возвращён классический
  POST-метод, который это поле поддерживает, но форма теперь **автоматически
  отправляется через JS сразу при загрузке страницы** — пауза перед реальным
  переходом на Payme сводится к времени, которое браузер тратит на разбор
  нескольких строк JS, и практически неотличима от прямого редиректа.
  Видимая кнопка «Продолжить» и ссылка «Отмена» оставлены как резерв на
  случай, если у покупателя заблокирован JavaScript.
- Убран параметр `ct` (был нужен только для GET-метода) — у POST-метода
  свой параметр `callback_timeout`, он передаётся так же, 15000 мс.

### 1.5.4

- Исправлено: на странице оплаты Payme после успешного платежа вместо
  обратного отсчёта и надписи о времени возврата на сайт отображалось
  «Вы будете автоматически перенаправлены на сайт поставщика через
  `{{ timeout }}`» — невставленный текст шаблона. Причина: GET-ссылка
  (внедрённая в 1.5.2) не передавала параметр `ct` (время в миллисекундах
  до авто-возврата после успешной оплаты), без которого фронтенд Payme не
  может подставить значение в свой шаблон. Добавлен `ct=15000` (15 секунд).

### 1.5.3 (хотфикс)

- Исправлена фатальная ошибка активации: `WC_Payment_Gateway` (родительский
  класс) уже объявляет свой собственный **публичный** метод `get_return_url()`.
  Новый в 1.5.2 приватный метод плагина случайно назывался так же, что
  запрещено в PHP (нельзя понижать видимость метода при наследовании) —
  `Fatal error: Access level to WC_PAYME::get_return_url() must be public`.
  Переименован в `get_payme_return_url()`. Функционально ничего не изменилось.

### 1.5.2

По просьбе убрать промежуточную страницу «Спасибо за заказ, нажмите Оплатить»
(как в плагине click.uz — там переход на страницу оплаты происходит сразу
после нажатия «Оформить заказ»):

- **`process_payment()` теперь возвращает прямую ссылку на Payme** —
  официальный GET-метод инициализации платежа
  (`https://checkout.paycom.uz/base64(m=...;ac.order_id=...;a=...;c=...;l=...)`).
  Промежуточная HTML-форма (`generate_form()`) удалена, покупатель после
  «Оформить заказ» сразу попадает на страницу оплаты Payme, в один переход,
  без остановки на своём сайте — так же, как это устроено в click.uz.
- Страница `receipt_page()` (используется при повторной попытке оплаты через
  «Мой аккаунт → Заказы → Оплатить») по той же причине тоже теперь сразу
  делает редирект на Payme, а не показывает форму.
- **Исправлен баг в URL возврата покупателя.** URL собирался конкатенацией
  строк (`return_url . '/' . order_id . '/?key=' . ...`), а `return_url` по
  умолчанию уже содержит `?payme_success=1` — получались **два `?` в одном
  URL**. Для WordPress всё, что после первого `?`, — единая строка запроса,
  поэтому `order_id` и `key` фактически никогда не доходили до обработчика
  как отдельные параметры. Теперь URL собирается через `add_query_arg()`.
- Заодно убран бессмысленный статичный флаг `payme_success=1` как признак
  «оплата прошла успешно» (он не менялся в зависимости от исхода платежа,
  только присутствовал в URL как есть) — теперь страница возврата определяет
  исход строго по актуальному статусу заказа.

### 1.5.1

Повторный аудит выявил логическую ошибку в связке `CreateTransaction` →
`PerformTransaction`, оставшуюся из версии 1.4.8 и не замеченную в 1.5.0:

- **`payment_complete()` тихо не срабатывал.** `CreateTransaction` переводил
  заказ в статус `processing` ещё до подтверждения оплаты. Метод
  `WC_Order::payment_complete()` в ядре WooCommerce выполняет свою основную
  логику (проставляет `_date_paid`, ID транзакции, вызывает хук
  `woocommerce_payment_complete`) **только если заказ на момент вызова
  находится в `on-hold`, `pending`, `failed` или `cancelled`** — `processing`
  в этот список не входит. Поэтому дата оплаты не сохранялась, а сторонние
  плагины, завязанные на `woocommerce_payment_complete` (отчёты, партнёрки,
  уведомления), не срабатывали. Промежуточный статус «транзакция открыта,
  ждём оплату» заменён на `on-hold` (штатный статус WooCommerce «Ожидает
  оплаты», единственный из некомплитных статусов, который `payment_complete()`
  действительно обрабатывает).
- **`state` в ответах Payme теперь не зависит от статуса заказа.** Раньше
  `state` вычислялся из `$order->get_status()`, который могут поменять
  вручную (например, менеджер вернул заказ в `on-hold` по причине,
  не связанной с оплатой) — это исказило бы ответы `CheckTransaction`/
  `CancelTransaction`. Теперь состояние транзакции всегда выводится из
  собственных меток времени плагина (`_payme_create_time`/`_perform_time`/
  `_cancel_time`), а статус заказа используется только как побочный эффект
  для витрины/логистики.
- Повторный вызов `CreateTransaction` для уже созданной транзакции теперь
  возвращает её реальное текущее состояние (1/2/-1/-2), а не всегда «1»,
  как того требует протокол Payme.
- Страница возврата покупателя (`payme_success`) обновлена: статус ожидания
  теперь `on-hold`, а не `pending` — иначе покупатель мог увидеть
  «Спасибо за покупку» раньше, чем Payme реально подтвердил платёж.

### 1.5.0

Существенная переработка `payme.php` по итогам аудита кода. Основные изменения:

**Критические исправления**
- Совместимость с WooCommerce **HPOS** (Custom Order Tables): все обращения к
  заказу переведены на CRUD API (`wc_get_order()`, `$order->update_meta_data()`,
  `$order->get_meta()`, `wc_get_orders()`) вместо прямых запросов к
  `wp_postmeta` и `new WC_Order()`. Добавлено объявление совместимости через
  `FeaturesUtil::declare_compatibility('custom_order_tables', ...)`.
- Исправлен баг двойного экранирования в SQL-запросе `get_order_by_transaction()`
  (лишние кавычки вокруг `%s` в `$wpdb->prepare()`), из-за которого
  `PerformTransaction`/`CheckTransaction`/`CancelTransaction` могли не находить
  заказ по транзакции. Запрос заменён на `wc_get_orders()`.
- `wc_get_order()` вместо `new WC_Order()` + явная проверка результата — вместо
  надежды на исключение, которое WooCommerce не всегда бросает при неверном ID.
- Добавлена обязательная по протоколу Payme проверка **тайм-аута транзакции
  (12 часов / 43 200 000 мс)**: неоплаченная транзакция теперь автоматически
  отменяется с причиной «Отмена по таймауту» (4) и кодом ошибки `-31008`.
- `CheckPerformTransaction` теперь проверяет не только сумму, но и то, что
  заказ вообще находится в состоянии, допускающем оплату.
- Сравнение Basic Auth credentials переведено на `hash_equals()` (защита от
  timing-атаки).
- Добавлен `exit` после `wp_redirect()` на странице возврата с оплаты.

**Прочие улучшения**
- Единая функция конвертации суммы в тийины (`to_tiyin()`) — раньше форма
  оплаты и callback считали сумму двумя разными способами.
- Страница успешной оплаты (`payme_success`) переписана: больше не перехватывает
  глобальные хуки `the_title`/`the_content` (что раньше могло затирать
  заголовки/контент виджетов и меню на той же странице). Вместо этого
  используются штатные `wc_add_notice()` и редирект на стандартную страницу
  WooCommerce «Заказ получен». Добавлена проверка order key перед показом
  статуса оплаты.
- Логирование ключевых событий (`CreateTransaction`, `PerformTransaction`,
  `CancelTransaction`, отказы авторизации) через `wc_get_logger()` —
  Статус → Логи → источник `payme`.
- Более устойчивое чтение заголовка `Authorization` (fallback на
  `PHP_AUTH_USER`/`PHP_AUTH_PW` для серверов, где `getallheaders()` его не отдаёт).
- Экранирование вывода (`esc_attr`, `esc_url`, `esc_html`) в форме оплаты и
  в настройках администратора.
- Добавлены заголовки `Requires PHP`, `Requires at least`, `WC requires at least`,
  `WC tested up to` в шапке плагина.
